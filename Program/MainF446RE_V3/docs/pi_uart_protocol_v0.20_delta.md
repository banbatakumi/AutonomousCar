# SURGE Mark.2 UART プロトコル — v0.19 → v0.20 差分

**日付**: 2026-10-09
**状態**: STM32 側・Pi 側とも実装済み・ビルド確認済み。**未書き込み、実機での動作検証は未了** (MD は変更なし)

v0.19 (`pi_uart_protocol_v0.19_delta.md`) からの差分のみを記す。**ワイヤ形式 (LEN・オフセット) は同じ**で、
既存の空きビットと `param_id` を1つずつ使う。きっかけは上位側リポジトリ
`surge_mk2/docs/cross_project_audit_2026-10.md` §4 の機能提案 6 (ローンチコントロール)。

---

## 0. 要約

1. **`COMMAND.flags2` bit3 `LAUNCH` を新設** (§1)。立っている間、車速指令の目標車速が車速より 0.5m/s 以上速い加速 (発進) で、目標車速の
   ランプと車速PIを迂回して全開のトルクを要求し、TC にグリップの限界へ絞らせる。
2. **`TELEMETRY.flags` bit24 `LAUNCH_ACTIVE` を新設** (§2)。ローンチコントロールで発進している最中。
3. **`param_id` `0x00A1` (`launch_exit_torque_nm`) を新設** (§3)。発進を終えて車速PIへ戻すときの積分の初期値。

**`protocol_version` は `0x0013` → `0x0014` に上がる。上位と一緒に入れ替えること** (上位の io_node は版が合わない
STM32 を ARM しない)。

## 1. `COMMAND.flags2` bit3 `LAUNCH` (ローンチコントロール)

### なぜ要るか

車速指令の加速は、目標車速を `accel_limit` (上限 `DRIVE_MAX_ACCEL_M_S2` = 3.0m/s²) でランプさせ、車速PI
(`DRIVE_SPEED_KP` 0.25・`DRIVE_SPEED_KI` 0.5) がそれを追う。PIは偏差が溜まるまでトルクが出ない: グリップの限界
(1輪 約0.09Nm = 総和 0.19Nm) を P 項だけで出すには偏差 0.76m/s が要り、3.0m/s² のランプでは約0.3秒かかる。
`torque_mode` の全開は最初の周期から TC がグリップの限界へ絞るので、この待ちが無い。

上位側 `tools/ctrl_tune` の車両モデル (同定した車 + あり得る車10台、`host/host_sim.c`) での比較
(効率 = 一定トルクの最良に対する、最初の1秒に進む距離の比):

| 発進のしかた | 効率 (平均) | 最悪の車 |
|---|---|---|
| `torque_mode` の全開 | 0.87 | 0.77 |
| 車速指令 3m/s (v0.19 まで) | 0.66 | 0.55 |
| 車速指令 3m/s + `LAUNCH` | 0.87 | 0.77 |

目標車速の 95% に届くまでの時間は、目標 1.0/1.5/2.0m/s のどれでも約0.18秒早い。PIへ戻したあとの行き過ぎは
平均 +0.01m/s・最悪の車で +0.10m/s (PI だけの発進は平均 +0.16・最悪 +0.36m/s)。

### 振る舞い (`src/control/drive.c` の `UpdateLaunch`。定数は `drive.h` の「ローンチコントロール」の節)

| | 条件 |
|---|---|
| 始める | `LAUNCH` が立っている・`target_speed` が車速より 0.5m/s (`DRIVE_LAUNCH_MIN_STEP_M_S`) 以上速い・目標と逆向きに 0.3m/s (`DRIVE_LAUNCH_REVERSE_SPEED_M_S`) 以上で動いていない・TC が有効。**車速は問わない** |
| 発進中 | 総トルクの要求 = ±`DRIVE_MAX_TORQUE_NM`×2 (`target_speed` の符号)。TV・TC・片輪浮き対策・速度超過の遮断はそのまま通る。目標車速 (ランプ後) は実車速に合わせ続ける |
| 終える | 車速が `target_speed` の 0.05m/s (`DRIVE_LAUNCH_END_MARGIN_M_S`) 手前に届いた / `LAUNCH` が下りた / `brake`・`torque_mode`・`side_brake`・フェイルセーフ・DISARM / TC が無効になった / 3秒 (`DRIVE_LAUNCH_TIMEOUT_S`) 経った |
| 終えたあと | 車速PIへ戻る。目標車速は今の車速から `accel_limit` で残りを詰め、積分は `launch_exit_torque_nm` (§3) から始める |

- **1回の要求で1回だけ。** `LAUNCH` を下ろす・制動する・止まって惰行する (`CoastStandstill`)、のどれかでまた使える。
  壁に当たって届かないまま時間切れしたあと、止まったまま全開を繰り返さないため。
- 後退 (`target_speed` < 0) も同じ式で働く。
- 徐行の指令 (目標との差が 0.5m/s 未満)・上位が自分で目標を刻む加速 (GUI の手動操作) では始まらない。
- **車速を条件にしていない。** 当初は「0.3m/s 未満から」だけにしていたが、上位の planner は走り出しで経路から
  15〜20cm 外れていて、経路に乗るまで 0.5m/s で走る。乗った時点ではもう動いているので、一度も働かなかった
  (上位側のシムの通し走行で発覚)。いつ要求するかは上位が決める (§4)。
- **空転を抑えるのは TC だけ**なので、TC が無効 (`param_id` `0x0010` = 0) なら始めない。前輪エンコーダが読めない
  ときは片輪浮き対策と後輪周速の絶対上限 (7.5m/s) が残るが、車速が上がらないので 3秒で打ち切られる。
- **`target_speed` は「そこまで全開で加速してよい速度」になる。** 立てる条件は上位の責任 (§4)。TC が保つスリップ率
  (`tc_slip_target`、上位の設定は 0.20) では横グリップが4割ほどしか残らない。

## 2. `TELEMETRY.flags` bit24 `LAUNCH_ACTIVE`

| bit | 名前 | 意味 |
|---|---|---|
| 24 | `LAUNCH_ACTIVE` | ローンチコントロールで発進している最中 (`Drive_IsLaunchActive`)。v0.20 で新設 |

`LAUNCH` を立てていても、条件を満たさず始まらなかった・もう終わった、なら立たない。発進中は TC が絞るので
`TC_ACTIVE` (bit5) も立つのが普通。

## 3. `param_id` `0x00A1` `launch_exit_torque_nm`

| `param_id` | 名前 | 既定 | 範囲 | 意味 |
|---|---|---|---|---|
| `0x00A1` | `launch_exit_torque_nm` | 0.0 | 0〜0.05 | 発進を終えて車速PIへ戻すときの積分の初期値 [Nm、1輪あたり] |

`control_params.h` の表の項目 (範囲外は丸めて `result=2`、Flash には保存しない。他の調整パラメータと同じ)。

発進中は車速PIを使わない (毎周期リセットする) ので、積分 0 でPIへ戻すと、その車速を保つトルク (転がり抵抗ぶん) が
積分に溜まるまで車速が落ち込む: 落ち込み = 保つトルクの総和 ÷ `DRIVE_SPEED_KP`、戻るのに約0.5秒
(車両モデルでは 0.12m/s)。保つトルクを積分の初期値に入れておけば落ち込まない。値が大きすぎれば同じだけ行き過ぎる
(誤差 0.005Nm あたり 0.04m/s)。上位は同定値 (転がり抵抗の減速度 ÷ トルク→加速度の利得 ÷ 2) から決めて送る。

## 4. 上位との組み合わせ

- 上位が `LAUNCH` を立てなければ、v0.19 と同じ動き (上位側 `tools/ctrl_tune` の全場面×車10台で、変更前後の出力が一致)。
- **今は手動操作でだけ使う** (2026-10-10)。上位の GUI は、止まった状態 (0.3m/s 未満) でブレーキとアクセルを両方
  踏み、ブレーキを離す、という手順を踏んだ発進の間だけ `LAUNCH` を立て、同時に `target_speed` を上限へ直接置く
  (GUI 側のランプを飛ばす)。ブレーキ中は `brake` が優先なので、準備の間に STM32 がすることは無い
  (ブレーキホールドで止まったまま。離した周期から発進する)。
- 上位の planner (`slam2d_raceline`・`slam2d_route`) は既定で立てない。有効にした場合に立てるのは**発進のときだけ**:
  車速が 0.3m/s 未満になってから経路の速度に届くまでの間で、経路に乗っていて、前が空いていて、舵が 0.12rad 未満の
  とき。周回中のコーナーの立ち上がりでは立てない。
- v0.19 の上位 + v0.20 の STM32、またはその逆は、上位の io_node が `protocol_version` の不一致で ARM を通さない。

## 5. 関連する変更 (プロトコル以外)

- `host/host_sim.c`: 入力の `IN_MODE` に 4 (車速指令 + `LAUNCH`) を、出力の `OUT_FLAGS` に bit4 (発進中) を足した。
  `HOST_SIM_ABI` 3 → 4。`Drive_SetLaunch` を持たない古い `src/control` (比較用に取り出したコミット) では、
  4 はただの車速指令になる (上位側 `tools/ctrl_tune/fw.py` が `HOST_FW_HAS_LAUNCH` を付けるかどうかを決める)。
