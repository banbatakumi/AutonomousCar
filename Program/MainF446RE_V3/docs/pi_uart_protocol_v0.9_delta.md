# SURGE Mark.2 UART プロトコル — v0.8 → v0.9 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-20
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要 (実機での動作検証は未了)**

v0.8 (`pi_uart_protocol_v0.8_delta.md`) からの差分のみを記す。
**変わったのは `CONFIG_SET`/`CONFIG_GET` で使える `param_id` が増えただけ**で、
`COMMAND`/`TELEMETRY` を含めどのパケットも構造・LEN は変わっていない。

---

## 0. 要約

後輪が片側だけ完全に浮いた (接地荷重ゼロ) ときにモーターが無負荷で回転数が張り付く
問題への対策として、「片輪浮き対策 (Wheel Lift Guard)」を追加した。既存のトラクション
コントロール (TC、前輪基準のスリップ率で判定) は低速域 (0.25 m/s 未満) で無効化される
ため、停止/低速からの片輪浮き急発進を捉えられない。新機構は前輪基準速度を使わず
「後輪左右の速度差」で判定するため、低速域でも機能する。TC本体とは独立した機構であり、
Pi から独立にON/OFFできる。

| 追加した操作 | 手段 |
|---|---|
| 片輪浮き対策の有効/無効切替 | `CONFIG_SET` の `param_id = 0x0050` |
| 現在の有効状態の取得 | `CONFIG_GET` の同じ `param_id` |

**`protocol_version` は `0x0008` → `0x0009` に上がる。**
`CONFIG_SET`/`CONFIG_GET` は元々未知の `param_id` に対して `RAS_CONFIG_UNKNOWN_PARAM`
を返す設計だったため、**Pi 側が未対応でも通信自体は継続する** (この `param_id` を
送らなければ既定 (有効) のまま変わらない)。

---

## 1. `CONFIG_SET` (0x11) / `CONFIG_GET` (0x13) — LEN 変更なし

### 1.1 `param_id` 一覧 ★追加

| param_id | 名称 | 型 | 値の意味 |
|---|---|---|---|
| 0x0050 | `wheel_lift_guard_enable` | f32 (bool 扱い) | 0.0 = 無効、非0 = 有効。既定は有効 |

- ペイロード形式は既存の `CONFIG_SET`/`CONFIG_GET`/`CONFIG_ACK` と同じ (`param_id` u16 +
  `value`/`applied` f32)。真偽値も他のパラメータと型を揃えるため f32 で送受信する。
- `CONFIG_ACK.applied` には実際に適用された値 (`0.0` か `1.0`) が入る。`value` に
  `0.0`/`1.0` 以外を送った場合、`(value != 0.0)` で真偽判定した上で `0.0`/`1.0` に
  丸めて適用し、丸めが発生した (元の値と一致しない) ぶん `result` は
  `RAS_CONFIG_OUT_OF_RANGE` になる (`tc_enable`/`tv_enable` と同じ量子化の扱い)。
- `0x0051` (片輪浮き対策のしきい値・ゲイン) は**未対応**。Drive 側がまだ定数でしか
  持っていないため、受信すると `RAS_CONFIG_UNKNOWN_PARAM` を返す。

### 1.2 片輪浮き対策の挙動

- トラクションコントロール (TC) 本体 (`param_id = 0x0010`) とは**独立**に動作する。
  「TCだけOFF」「片輪浮き対策だけOFF」「両方OFF」を個別に指定できる。
- 有効時、後輪左右の速度差 (ヨーレートで期待される差を差し引いた異常成分) が
  しきい値を超えると、速い方 (浮いていると推定される輪) だけトルク上限を削る。
  正常な接地輪側は絞らない。
- 加えて、後輪周速が物理的にあり得ない絶対値 (`DRIVE_MAX_SPEED_M_S` の1.5倍) を
  超えたときは、左右差の判定結果に関係なく即座にトルク上限を0にする最終防波堤を持つ。
- 無効にすると、この機構によるトルク上限の削り込みを一切行わない (TC本体が有効なら
  そちらのスリップ率ベースの削り込みは引き続き効く)。
- 設定はマイコン起動時・COMMAND 未受信中は既定 (有効) に戻る。COMMAND が生きている
  間は毎周期、直近に `CONFIG_SET` で設定された値が適用され続ける。

## 2. Pi 側の対応チェックリスト

- [ ] `protocol_version` の期待値を `0x0008` → `0x0009` にする
- [ ] 片輪浮き対策を切り替えたい場合のみ `CONFIG_SET` (`param_id = 0x0050`) を送る
      (送らなければ既定で有効のまま変わらない)
- [ ] 現在の設定値を確認したい場合は `CONFIG_GET` で同じ `param_id` を問い合わせる
- [ ] **実機での動作検証は STM32 側でも未実施。** しきい値 (後輪左右速度差の異常検知、
      絶対車輪速上限) は実測前の机上値であり、誤介入が疑われる場合は一度 OFF にして
      切り分けることを推奨する
