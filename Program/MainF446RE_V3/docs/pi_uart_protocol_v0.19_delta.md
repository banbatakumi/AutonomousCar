# SURGE Mark.2 UART プロトコル — v0.18 → v0.19 差分

**日付**: 2026-10-09
**状態**: STM32 側・Pi 側・MD 側とも実装済み・ビルド確認済み。**いずれも未書き込み、実機での動作検証は未了**

v0.18 (`pi_uart_protocol_v0.18_delta.md`) からの差分のみを記す。**ワイヤ形式 (LEN・オフセット) は同じ**で、
変わるのは `TELEMETRY.flags`・`md_status` の**ビットの意味と追加**、および「止める」ときの**振る舞い**。
きっかけは 3 リポジトリ横断の調査 (上位側リポジトリ `surge_mk2/docs/cross_project_audit_2026-10.md`)。

---

## 0. 要約

1. **`TELEMETRY.flags` bit2 `ARMED` の意味を「駆動電源 ON」から「上位の指令で走れる状態」へ変えた** (§1)。
   駆動電源の状態は新設の bit22 `DRIVE_POWER_ON`。
2. **bit23 `MD_FAULT` を新設** (§2)。MD (3台のいずれか) が使えないため走行を止めている。
3. **`md_status` bit6 `UNCALIBRATED` を新設** (§3)。MD のエンコーダが未校正。
4. **走行中に ARM が外れても、停車するまで駆動電源を切らず最大制動する** (§4)。
5. **ARM されても、3台の MD が使える状態になるまで `ARMED` にしない** (§2)。
6. **`COMMAND.steer_rate_limit` = 0 のときの既定値を 0.5 rad/s の定数にした** (§5。値はほぼ同じ)。

**`protocol_version` は `0x0012` → `0x0013` に上がる。上位と一緒に入れ替えること** (§6)。

## 1. `TELEMETRY.flags` bit2 `ARMED` / bit22 `DRIVE_POWER_ON`

| bit | 名前 | 意味 |
|---|---|---|
| 2 | `ARMED` | 直近の周期で上位の指令を ARM として適用した (`Vehicle_IsArmed`)。**この間だけ車速・舵角の指令が効く** |
| 22 | `DRIVE_POWER_ON` | 駆動電源 (DRIVE_POWER) が入っている (`Power_IsDriveOn`)。v0.19 で新設 |

v0.18 までの `ARMED` は駆動電源の状態で、次のとき「走れないのに立つ」:

- ステア中心が未較正 (v0.19 からはそもそも駆動電源を入れない。§4)
- MD の起動待ち (給電から約 1 秒)
- `mode` が MANUAL/AUTO 以外
- ARM が外れたあと、停車を待って制動している間 (§4)

`ARMED` = 1 なら必ず `DRIVE_POWER_ON` = 1。逆は成り立たない。

## 2. bit23 `MD_FAULT` と MD の健全性

走行制御は MD の状態を見ずにトルクを指令するので、v0.18 までは片側の後輪 MD が過熱・電圧異常で止まっても
反対側は駆動を続け、ステア MD が止まっても舵が効かないまま走り続けた。v0.19 からは、駆動電源が入っている間
3台の MD を毎周期監視する (`UpdateMdHealth`、`src/vehicle/vehicle.c`)。

MD 1台が「使える」(`Motors_NotReadyReason` が NULL) とは:

- 状態フレームが届いている (100ms 途絶で不可。`md_status` の `COMM_OK`)
- 異常ビット (過電流・過熱・電源電圧・エンコーダ未校正) が立っていない
- こちらが指令したトルク上限を MD が適用している (`LIMIT_SYNCED`)

| 状況 | `ARMED` | `MD_FAULT` | 振る舞い |
|---|---|---|---|
| 駆動電源を入れて 3台が揃うのを待っている (通常 約1秒) | 0 | 0 | 走らせない (車速 PI も回さない) |
| 3台が揃った | 1 | 0 | 通常どおり |
| 5 秒 (`VEHICLE_MD_BOOT_TIMEOUT_S`) 待っても揃わない | 0 | **1** | 走らせない |
| 走行中にどれかが使えなくなった | 1 | **1** | **両後輪を最大制動**。上位の車速・トルク指令は無視 (舵角は効く) |

- `MD_FAULT` は**駆動電源が切れるまでラッチ**する (MD が復帰しても勝手に走り出さない)。上位が ARM を外し、
  停車して電源が落ちれば解除される。
- どの MD がなぜ使えないかは `LOG` (ERROR) で1回だけ送る: `MD rear-left stopped: overheat` など。
  理由は `no response` / `overcurrent` / `overheat` / `supply voltage out of range` /
  `encoder not calibrated` / `torque limit not applied`。
- `torque limit not applied` は、MD 側の絶対上限 (Kt × 最大電流。校正値で決まる) がこちらの指令
  (後輪 0.15 N·m・ステア 0.10 N·m) より小さい個体でも出る。

## 3. `md_status`

| bit | 名前 | 意味 |
|---|---|---|
| 0 | `RUNNING` | MD が**受理済みの指令を実行中** (停止モードでない)。「回転中」ではない (意味は以前から同じ。名前が紛らわしいので明記) |
| 6 | `UNCALIBRATED` | MD のエンコーダが未校正。MD は制限値を受け付けず動かない。v0.19 で新設 (MD 側の status bit4) |

MD は異常中も状態フレームを通常の周期 (2kHz) で返すようになった (以前は約 1Hz に落ちていた)。

## 4. ARM が外れたときの駆動電源

v0.18 までは `COMMAND.flags` の ARM ビットがそのまま駆動電源だった。上位は通信途絶・デッドマンで
`mode=0, flags=0` を送ってくるので、走行中に Wi-Fi が切れると MD ごと電源が落ち、**制動せず惰行**していた
(`COMMAND` 自体は届き続けるので「途絶 100ms で最大制動」も働かない)。

v0.19:

- 駆動電源が入っている状態で ARM が外れたら、**|車速| が 0.05 m/s (`DRIVE_STANDSTILL_SPEED_M_S`) を下回るまで
  最大制動を続けてから電源を切る**。上限は 3 秒 (`VEHICLE_DISARM_BRAKE_TIMEOUT_S`)。
- この間 `ARMED` = 0・`DRIVE_POWER_ON` = 1。舵角は最後の値のまま保持する。
- 途中で ARM が戻れば、MD は起動済みなのですぐ `ARMED` に戻る。
- **ステア中心が未較正の間は、ARM されても駆動電源を入れない** (`STEER_CENTER_VALID` = 0)。v0.18 までは電源が入り、
  ステア MD へ「未較正の中心 0 rad」を基準にした位置指令が届いてステアが動いた。

停車中に ARM を外した場合は、これまでどおりその周期に電源が切れる。

### フェイルセーフの停車保持

緊急停止・`COMMAND` 途絶 (`ApplyFailsafe`) は最大制動で止めたあと、停止 (|車速| < 0.1 m/s) が 1 秒続いたら
**後輪の位置保持** (サイドブレーキと同じ仕組み) へ移る。MD の制動は車輪が止まる手前でトルクが抜けるので、
それだけでは坂で保持できなかった。位置保持に入っている間は `SIDE_BRAKE_ACTIVE` (bit17) が立つ。

## 5. `COMMAND.steer_rate_limit` = 0

0 (指定なし) のときの上限は `VEHICLE_DEFAULT_STEER_RATE_RAD_S` = 0.5 rad/s。v0.18 までは「最大舵角 [rad] の数値」
(0.46〜0.52) を rad/s として流用していた。値はほぼ同じで、単位の合う定数にしただけ。

## 6. 上位との組み合わせ

| ファーム | 上位 | 起きること |
|---|---|---|
| v0.19 | v0.19 | 正しい |
| v0.18 以前 | v0.19 | 上位は版の不一致を検出して **ARM しない** (v0.19 の上位から。`link/diag` に理由が出る) |
| v0.19 | v0.18 以前 | 動くが、上位の `armed` 表示が MD の起動待ち (約1秒) の間 0 のままになる。bit22/23 は無視される |

MD (BLDC) 側のファームは新旧どちらでも通信できる (状態フレームの bit4 が増えただけ)。ただし
「異常中も状態フレームを 2kHz で返す」「異常からの復帰時に古い指令を捨てる」は新しい MD ファームだけ。

## 7. 関連する変更 (プロトコル以外)

- **`Coast()` は送信を止めず、トルク 0 を送り続ける** (`src/control/drive.c`)。MD は無通信 0.5 秒で停止モードに
  入るまで直前のトルクを出し続けるため、停車判定で惰行に入ったあとも減速中の負トルクが残り、後退していた。
  `host/` の車両モデルは以前から「停止 = 即トルク 0」として扱っており、実機がモデルに揃った
  (`tools/ctrl_tune` の bench は変更前後で一致)。
- **IMU の I2C 復旧をブロッキングしないステートマシンにした** (`src/sensing/imu.c` の `StepRecovery`)。
  以前は約 190ms メインループを止めていた。
- **ジャイロのレンジを ±250 → ±500 deg/s に広げた** (`lib/mpu6050`)。フルステア約 1.75 m/s 以上で飽和していた。
  Flash の較正値 (LSB 単位) は読み込み時に換算して引き継ぐ。`TELEMETRY.yaw_rate` の単位・スケールは変わらない。
- 超音波は ARM していない間、無効値 (0) を返す (以前は止める前の値が有効値として残った)。
- `CONFIG_ACK` などの送信キューを 256 → 512 バイトにした (接続時の連続 `CONFIG_SET` で溢れていた)。
