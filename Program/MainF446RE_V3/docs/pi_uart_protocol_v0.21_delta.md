## 1. 車速PIの加速度フィードフォワード

### なぜ要るか

車速指令は、目標車速を `accel_limit` の傾きで動かし、車速PI (`DRIVE_SPEED_KP` 0.3・`DRIVE_SPEED_KI` 0.6) が
それを追う。PI は偏差が無いとトルクを出せない: 加速度 `a` を出すには偏差が `a ÷ (車体の利得 × Kp)` だけ要り、
車速は目標に `1 ÷ (車体の利得 × Kp)` ≒ 0.15 秒遅れる (車体の利得 21.5 (m/s²)/Nm は上位のシステム同定の値)。
上位は経路の速度プロファイルどおりに目標を送るので、コーナーの手前の減速がその分遅れ、0.3〜0.5m/s 速く入る
(実車 2026-10-06)。上位側で目標を前倒しして埋めていたが、前倒しの量は実験で合わせた係数だった。

目標車速の傾きは Drive 自身が作っているので分かっている。**その加速に要るトルクを先に足せば**、PI は残った
ずれ (モデルの誤差・勾配・TC の介入) だけを直せばよく、遅れは通信とローパスのぶん (約 40ms) まで縮む。

### 仕様 (`src/control/drive.c` の `SpeedFeedforward()`、`drive.h` の同名の節)

車速PIを通る周期 (制動・サイドブレーキ・トルク指令・ローンチコントロール・停車の惰行**以外**) に、

```
step     = この周期に目標車速を動かした量 [m/s]      (= Constrain(setpoint − target, ±accel_limit×dt))
a_ref   += (step/dt − a_ref) × dt / (DRIVE_SPEED_FF_TAU_S + dt)        (1 次ローパス、20ms)
T_ff     = speed_ff_nm_per_m_s2 × a_ref
         + speed_ff_rr_nm × sign(目標車速)            (|目標車速| ≥ DRIVE_STANDSTILL_SPEED_M_S のときだけ)
要求トルク = Constrain(PI の出力 + T_ff, ±DRIVE_MAX_TORQUE_NM×2)
```

- ローパスは、上位が 50Hz で目標を刻むので `step/dt` が「届く前は `accel_limit`、届いた周期は 0」と跳ぶのを
  ならすため。**上位はこの時定数ぶん先の速度を送る** (Pi 側 `raspi/nav/speedctl.py` の `FW_FF_TAU_S`、シムの
  `sim/vehicle.py` の `SpeedController.FF_TAU_S` と同じ値にすること)
- 車速PIを通らない周期は `a_ref` を 0 に戻す (制動を解いた直後に古い傾きのトルクを出さない)
- TC・リミッタで削られた分の積分の巻き戻し (`UnwindIntegral`) は、足した後の要求と実際に出したトルクの差で
  行う (従来どおり)。フィードフォワードがグリップを超える要求になっても TC が絞り、積分は巻き戻る

### `param_id`

| `param_id` | 名前 (`control_params.h`) | 単位 | 範囲 | 既定 |
|---|---|---|---|---|
| `0x00B1` | `speed_ff_nm_per_m_s2` | N·m/(m/s²)、後輪 2 輪の合計 | 0〜0.2 | 0 (無し) |
| `0x00B2` | `speed_ff_rr_nm` | N·m、後輪 2 輪の合計 | 0〜0.05 | 0 (無し) |

値の決め方 (上位のシステム同定、`config/vehicle.toml` の `[dynamics]`):

- `speed_ff_nm_per_m_s2` = 1 ÷ `speed_plant_gain` (2026-10-11 の値で 1 ÷ 21.52 = 0.0465)
- `speed_ff_rr_nm` = `rolling_resistance` ÷ `speed_plant_gain` (0.273 ÷ 21.52 = 0.0127)

上位は `[control]` に書いた値を接続のたびに送り、同定を適用すると `tools/sysid` が書き直す。

### 上位の指令の出し方 (参考)

フィードフォワードは「目標車速の傾き」に効くので、上位 (slam2d 系の planner) は `COMMAND` に

- `target_speed` = 指令が効くころ (半周期 10ms ＋ 通信 ＋ ローパス 20ms 先) に居る場所のプロファイルの速度
- `accel_limit` = そこでのプロファイルの加速度 (の 1.1 倍、下限 0.3m/s²)

を入れる。速度を急に抑えるとき (障害物など) は `accel_limit` を指定しない (= 上限 3.0m/s²)。

## 2. 確かめたこと・残り

- ファームのビルド (`make`) は通る。`src/control` のホストでの回帰テスト (上位 `tools/ctrl_tune/tests`) は
  既定値 (0 = 無し) のまま走るので、従来の動きが変わらないことだけを見ている
- 効きは上位のシム (ファームの写し `sim.vehicle.SpeedController` に同じ式) で確かめた: 1 次元の周回で
  コーナー進入の出過ぎ 0.47m/s (何もしない) → 0.12 (上位側の前倒し) → 0.09 (これ)、追従の誤差 0.154 → 0.047 →
  0.025m/s。利得を ±20% 外しても 0.11 以下
- **未書き込み・実機未検証。** 実機では、直線の加減速 (上位の前後運動試験) の記録で車速が目標に遅れないこと、
  TC の介入が増えていないことを見る
