# SURGE Mark.2 UART プロトコル — v0.5 → v0.6 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-11
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要**

v0.5 (`pi_uart_protocol_v0.5_delta.md`) からの差分のみを記す。
**変わったのは `COMMAND` (0x10) だけ**で、`TELEMETRY` / `LIDAR_SECTOR` / `PING` / `CONFIG_*` /
`VERSION` / `STATS` のレイアウトは v0.5 のまま一切変わっていない。

---

## 0. 要約

GUI/AUTO から後輪へ**トルクを直接指令**できるようにするための変更である。

| 追加した操作 | 手段 |
|---|---|
| 駆動トルクの直接指令 [N·m] | ペイロード末尾に `target_torque : i16` を追加 (**LEN 12 → 14**) |
| 直接指令モードへの切替 | `flags` bit6 に `torque_mode` を新設 |

**`protocol_version` は `0x0005` → `0x0006` に上がる。**
`COMMAND` の LEN が変わるため、**Pi 側を更新するまで走行指令は一切通らない**
(STM32 は LEN 不一致のフレームを破棄し `STATS.rx_len_error` に計上する)。

---

## 1. `COMMAND` (0x10) — LEN = 12 → **14**

```
off  size  type    field                 単位 / 備考
──────────────────────────────────────────────────────────────────────────────
  0    1   u8      mode                  0=DISARM / 1=MANUAL / 2=AUTO / 3=予約   (変更なし)
  1    1   u8      flags                 §1.1 ★ビット追加
  2    2   i16     target_speed          0.001 m/s                               (変更なし)
  4    2   i16     target_steer          0.0001 rad 路面舵角、反時計回り正        (変更なし)
  6    2   u16     accel_limit           0.001 m/s²  0 = 未指定 (設定値を使う)   (変更なし)
  8    2   u16     steer_rate_limit      0.001 rad/s 0 = 未指定                  (変更なし)
 10    2   u16     brake_torque          0.0001 N·m  0 = 未指定 (最大で制動)     (変更なし)
 12    2   i16     target_torque         0.0001 N·m  負=後退方向 ★新規
──────────────────────────────────────────────────────────────────────────────
                                                            合計 14 バイト
```

**フレーム長 = 14 + 7 = 21 バイト。100Hz で 2.10 kB/s。**

### 1.1 `flags` (u8) ビット定義 ★変更

| bit | 名称 | 意味 | v0.5 からの変化 |
|---|---|---|---|
| 0 | `arm` | 駆動電源投入を要求 | 変更なし |
| 1 | `brake` | ブレーキを掛ける (`torque_mode` より優先) | 変更なし |
| 2 | `horn` | クラクション (押している間だけ鳴る) | 変更なし |
| 3-4 | `light_mode` | 前照灯モード | 変更なし |
| 5 | `passing` | パッシング | 変更なし |
| 6 | `torque_mode` | 立っている間 `target_speed` を無視し、`target_torque` を後輪へ直接指令する | **★新規** |
| 7 | — | 予約 (0 を入れること) | — |

### 1.2 `target_torque` (i16, 0.0001 N·m/LSB, 負=後退方向) ★新規

後輪 **各輪** へ直接指令する駆動トルク。`flags.torque_mode` が立っているときだけ意味を持つ。

- **`0` は「未指定」ではなく素直に「駆動トルク 0」を意味する。** `brake_torque` とは約束が違うので注意
  (書き忘れは「動かない」側に倒れるだけなので、0 を安全側の既定値へ読み替える必要が無い)。
- STM32 側の上限は **±0.1 N·m/輪** (`DRIVE_MAX_TORQUE_NM`、モータ物理上限 0.1557 N·m 未満) で、
  超える値は STM32 側でもクランプされる。Pi 側のクランプに頼らないこと。
- **`torque_mode` 中は車速 PI ループが迂回される。** `target_speed` は無視される。
  左右への配分は等配分 + トラクションコントロール (TC) のリミッタ + トルクベクタリング (TV) の
  ヨーモーメント項を、通常の駆動時と同じ経路で適用する
  (**空転抑制のため TC/TV は掛けたままにする**という方針で実装した)。
- **`brake` と `torque_mode` が同時に立っていたら `brake` が優先される。** ブレーキ中は
  `target_torque` は無視される。
- `torque_mode` を離すと目標車速 0 から加速し直す (レート制限は `accel_limit` に従う)。
  `brake` と同じ扱いで、離した瞬間に飛び出すことはない。

### 1.3 `TELEMETRY.torque_cmd[2]` との関係 (レイアウトは変更なし)

`torque_cmd` は引き続き「TC 適用後の最終指令トルク (正=駆動、負=制動)」を報告する。
`torque_mode` 中に TC が介入して削られていれば、その削られた後の値が `torque_cmd` に出る
(= `target_torque` をそのまま返しているわけではない)。
