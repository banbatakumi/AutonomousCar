# SURGE Mark.2 UART プロトコル — v0.12 → v0.13 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-28
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要 (実機での動作検証は未了)**

v0.12 (`pi_uart_protocol_v0.12_delta.md`) からの差分のみを記す。
変わったのは `TELEMETRY` (0x03) の LEN・末尾に追加された4フィールドと、`COMMAND` (0x10) の
LEN・新設 `flags2` バイトのみ。他のパケットに変更はない。

---

## 0. 要約

TC (トラクションコントロール本体) のゲイン (`DRIVE_TC_CUT_GAIN`/`DRIVE_TC_RECOVER_RATE`) を
実機で追い込むため、TCの内部状態を `TELEMETRY` に追加した。従来は `TC_ACTIVE` フラグ
(介入中かどうかの1bit) しか上位から見えず、実際にどれだけ介入しているか・発振していないかを
判断できなかった。

加えて、後輪モータを位置制御に切り替えて機械的に固定する「サイドブレーキ」を追加した。
`COMMAND.flags` (0x10) は8bit全て使用済みのため、新バイト `flags2` を追加して伝える。

**`protocol_version` は `0x000C` → `0x000D` に上がる。`TELEMETRY` の LEN は 66 → 74、
`COMMAND` の LEN は 14 → 15。**

---

## 1. `TELEMETRY` (0x03) — LEN 66 → 74

`torque_cmd_nm[2]` (RL, RR) の直後に、以下2フィールドが追加される。

| オフセット (旧LEN=66からの相対位置) | 内容 | 型 | スケール |
|---|---|---|---|
| +0–3 | `slip` | **i16×2** | ×0.0001 (無次元) [RL, RR] |
| +4–7 | `tc_limit_nm` | **i16×2** | ×0.0001 N・m [RL, RR] |

- `slip[]`: 後輪のスリップ率。正 = 空転、負 = ロック傾向。基準速度が低速で無効な区間
  (`DRIVE_TC_MIN_SPEED_M_S` 未満) は 0 が入る。
- `tc_limit_nm[]`: TC が動的に決めているトルク上限。`DRIVE_MAX_TORQUE_NM` (0.15 N・m) が
  「制限なし」を意味し、それより小さければ介入中。`torque_cmd_nm[]` (実際に送ったトルク) と
  合わせて見ることで、「PIDが欲しがっている量」に対して「TCがどこまで絞っているか」が分かる。

パケット全体のフィールド順序 (v0.13時点、変更箇所のみ抜粋):

```
... motor_current_a[3] (f32→i16×3) ...
torque_cmd_nm[2]  (f32→i16×2, ×0.0001 N・m)
slip[2]           (f32→i16×2, ×0.0001)          ★追加
tc_limit_nm[2]    (f32→i16×2, ×0.0001 N・m)      ★追加
temp_c[4] ...
```

## 2. `COMMAND` (0x10) — LEN 14 → 15

既存14バイトの末尾に `flags2` (uint8, 1バイト) が追加される。

| オフセット | 内容 | 型 |
|---|---|---|
| 14 | `flags2` | u8 (bit0 = `SIDE_BRAKE`) |

- `flags2` bit0 (`SIDE_BRAKE`): 立っている間、指令を受けた瞬間の後輪モータ機械角度を目標値
  としてラッチし、位置制御へ切り替えて機械的に固定する (パーキングロック)。**速度に関わらず
  即座に切り替わる** (停止を待たない)。既存の `flags` bit1 (`BRAKE`) より優先する。
  Pi 側が明示的にこのビットを下ろさない限り有効なまま (`brake` と同じ「送り続けている間だけ
  有効」な継続コマンド)。
- MD の状態フレームが無効 (給電直後など) でラッチする角度が取れない間は、通常の最大トルク
  制動へ自動的にフォールバックする。実際に位置保持へ入ったかどうかは `TELEMETRY.flags` の
  `SIDE_BRAKE_ACTIVE` (下記) で確認できる。

## 3. `TELEMETRY` (0x03) — `flags` (bit17) 追加

`RAS_FLAG_SIDE_BRAKE_ACTIVE (1u << 17)`: サイドブレーキが実際に位置制御へ切り替わって
固定中かどうか。要求中でも上記フォールバック中の間は立たない。`TELEMETRY` の LEN・
既存フィールドへの影響はない (`flags` は元々 `uint32_t` で確保済み)。

## 4. Pi 側の対応チェックリスト

- [ ] `protocol_version` の期待値を `0x000C` → `0x000D` にする
- [ ] `TELEMETRY` のパース長を 66 → 74 バイトに変更し、末尾に `slip[2]`・`tc_limit_nm[2]`
      (いずれも i16、×0.0001 でデコード) を追加する
- [ ] 対応が不要なら `TELEMETRY` を無視してよいが、LEN 不一致で破棄されないよう
      パース処理は必ず新しい LEN に追従させること
- [ ] **実機での動作検証は STM32 側でも未実施。** `DRIVE_TC_CUT_GAIN`/`DRIVE_TC_RECOVER_RATE`
      は実測前の机上値であり、このテレメトリを使って発振 (`tc_limit_nm` の周期的な増減) が
      無いか、介入が遅すぎ/戻りが遅すぎないかを確認しながら追い込む想定
- [ ] `COMMAND` の送信長を 14 → 15 バイトに変更し、末尾に `flags2` (u8) を追加する
      (STM32 側は固定長ぴったりでないと LEN エラーで破棄するため、旧14バイトのままでは
      COMMAND 自体が届かなくなる)
- [ ] サイドブレーキを使う場合は `flags2` bit0 を立てて送り続け、解除時は下ろす
- [ ] `TELEMETRY.flags` の bit17 (`SIDE_BRAKE_ACTIVE`) をデコードし、要求と実際の固定状態の
      ずれ (MDデータ無効によるフォールバック中) を UI 等で区別できるようにする
- [ ] **サイドブレーキも実機での動作検証は未実施。** 特に「速度に関わらず即座に位置制御へ
      切り替える」仕様のため、走行中に誤って `flags2` bit0 を立てないよう Pi 側の指令生成
      ロジックでも注意すること
