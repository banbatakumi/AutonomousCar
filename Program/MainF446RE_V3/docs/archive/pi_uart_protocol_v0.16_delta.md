# SURGE Mark.2 UART プロトコル — v0.15 → v0.16 差分

**日付**: 2026-10-05
**状態**: STM32 側・Pi 側とも実装済み・ビルド確認済み。**STM32 は未書き込み、実機での動作検証は未了**

v0.15 (`pi_uart_protocol_v0.15_delta.md`) からの差分のみを記す。変わったのは `CONFIG_SET`/
`CONFIG_GET` の `param_id` の追加と、**`TELEMETRY` (0x02) の LEN 74 → 84** (制御の介入量を追加、§4)・
`flags` bit21。STM32 側の足回りの制御 (TC・ABS・片輪浮き対策・TV) の中身も変わったので、
同じ指令でも挙動は変わる。

---

## 0. 要約

1. **調整パラメータを実行時に読み書きできる** (§1)。値は Flash に保存しない。上位は接続の
   たびに全項目を送り、`CONFIG_ACK.applied` と突き合わせること。
2. **TC・ABS をスリップ率の連続 PI へ作り直した** (§2)。低速でも働き、TC は車速PIの減速にも掛かる。
3. **片輪を絞った分を反対の輪へ載せない**。片輪浮き対策は TC と同じ上限を共有する (§2)。
4. **TV**: 左右差を保つ配分・規範ヨーレートの1次遅れ・同定用のヨーモーメント注入 (§3)。
5. **`TELEMETRY` に制御の介入量を追加** (§4)。上位のグラフ・記録で「どれだけ絞ったか」が分かる。
6. `src/control` をホスト (Mac) でコンパイルして車両モデルと閉ループにする `host/` を追加した
   (`host/README.md`。上位側リポジトリの `tools/ctrl_tune` が比較・最適化に使う)。

**`protocol_version` は `0x000F` → `0x0010` に上がる。**

## 1. `CONFIG_SET` / `CONFIG_GET` — 調整パラメータ

**名前・`param_id`・既定値・範囲の唯一の定義は `src/control/control_params.h` の表**
(`CONTROL_PARAM_TABLE`)。ここへ写した一覧は説明用で、食い違ったら表が正。

| param_id | 名前 | 既定 | 範囲 | 内容 |

| `0x0021` | `tv_kp_nm_per_rad_s` | 0.08 | 0〜2.0 | TV の比例ゲイン |

- 範囲外の値は範囲内へ丸めて入れ、`CONFIG_ACK.result = 2` (範囲外)・`applied` = 丸めた後の値。
  非数は既定値にする。表に無い `param_id` は従来どおり `result = 1`。
- 既定値は「上位が何も送らなくても安全に走れる値」(上位側の車両モデルで決めた初期値)。
  `0x0030`/`0x0031` (速度PIのゲイン) は引き続き未対応。
- 走行中でも受け付ける (ARM 中の変更を拒まない)。上位は走行中に調整値を変えないこと
  (同定用の `tv_test_moment_nm` と機能の ON/OFF だけが走行中に変わる想定)。
- 既存の ON/OFF (`0x0010` TC・`0x0020` TV・`0x0050` 片輪浮き対策・`0x0070` ABS) は変更なし。

実装: `ControlParams` を `RasConfig.control` が持ち、`ApplyRasCommand()` が毎周期
`Drive_SetParams()` へ写す (ON/OFF と同じ経路)。

## 2. TC・ABS・片輪浮き対策 (`src/control/drive.c`)

説明の本体は `src/control/drive.h` の「スリップ制限」の節。上位から見える違いだけを挙げる。

- **スリップ率の分母に下限** (`slip_speed_floor_m_s`): スリップ率 = スリップ速度 /
  max(|基準速度|, 下限)。以前は基準速度 0.25 m/s 未満で TC・ABS ごと無効にしていた。
  **`TELEMETRY.slip[2]` は低速でも 0 にならない** (進行方向は基準速度と車輪速の和の符号)。
- **連続の PI** (`SlipLimiter`): 目標スリップ率を超えたら、そのとき掛けていたトルクを積分の
  初期値にして働き始め、上限 = 積分 + kp×偏差。上限が要求以上に戻ったら止まる。以前の
  「覚えて0.7倍 → 25ms → 0.9倍 → 0.2Nm/s」(油圧 ABS を写したルール) は廃止。
- **TC は車速PIの減速にも掛かる**: 制御が見るのは「トルクを掛けている向きのスリップ速度」で、
  駆動の空転も減速のロック傾向も同じ式で扱う。以前は車速PIの減速は対象外だった
  (目標車速のランプ 3.0 m/s² は後輪だけの制動で出せる減速度を超える)。
- **片輪を絞っても、その分を反対の輪へ載せない** (総駆動力が減る)。以前は左右差を丸める
  ときに総和を保つ方を優先し、絞った分を反対の輪へ押し増していた。
- **片輪浮き対策**: 後輪左右の速度差 (ヨーレートで説明できる分を除く) が
  `wheel_lift_diff_threshold_m_s` を超えたら、先走っている輪を TC と同じ PI で絞る。TC の偏差と
  小さい方を使うので、上限は1つ (`TELEMETRY.tc_limit_nm[2]` に両方が出る)。ON/OFF は独立のまま。
  後輪周速の絶対上限は 7.5 m/s (`DRIVE_MAX_SPEED_M_S` × 1.5。以前のコメントの 4.5 は誤記)。
- **ABS**: 左右共通 (select-low) は変更なし。フォールバックは「上限が要求の20%以下に 0.2 s」
  (以前は 0.1 s。PI は以前の段階的な下げ方より速く下がるので、検知までの合計時間を揃えた)。
- `RAS_FLAG_TC_ACTIVE` は「TC の上限が実際にトルクを削った」(片輪浮き対策の偏差の方が
  効いていた周期は含めない)。

## 3. TV (`src/control/torque_vectoring.c`)

- **左右差を保つ配分**: 片方がトルクの絶対上限に当たったら、左右差を保ったままもう片方を
  同じだけ下げる (総駆動トルクが減る)。以前は総和を保つために差を丸めていて、全開
  (両輪とも上限) では差がまったく付かなかった。
- **積分の巻き戻し**は「要求した差のうち実際に効いた分」で行う。TC が片輪を絞って生じた
  左右差は TV の出力ではないので除く。
- **規範ヨーレートの1次遅れ** (`tv_ref_lag_s`。既定 0 = なし)。
- **規範の定数を調整パラメータへ**: `tv_steer_gain`・`tv_steer_gain_cubic`・
  `tv_max_lateral_accel_m_s2` は上位が同定結果から送る (以前は定数へ手で写していた)。
- **同定用のヨーモーメント注入** (`tv_test_moment_nm`): 0 以外の間、PI を止めてこの
  ヨーモーメントだけを出す (左旋回方向が正。`tv_max_yaw_moment_nm` で頭打ち)。TV が有効・
  IMU が正常・車速 0.30 m/s 以上のときだけ出る。

## 4. `TELEMETRY` (0x02) — LEN 74 → 84、`flags` bit21

`tc_limit_nm[2]` の直後 (オフセット 60) に 10 バイトを追加した。以降のフィールド (`temp[4]` 〜
`cmd_seq_echo`) は 10 バイト後ろへずれる。

| off | 型 | 名前 | 単位 | 内容 |
|---|---|---|---|---|
| 60 | i16×2 | `torque_req[2]` | 0.0001 N·m | [RL, RR] スリップ制限 (TC・片輪浮き対策・ABS) が絞る前に掛けたかったトルク。駆動は TV の左右差を載せた後、制動は要求の制動トルク (負)。**`torque_cmd` との差が絞った量** |
| 64 | i16 | `abs_limit_nm` | 0.0001 N·m | ABS が決めている制動トルクの上限 (左右共通)。働いていなければ最大トルク |
| 66 | i16 | `yaw_rate_target` | 0.001 rad/s | TV の規範ヨーレート (IMU が使えない間は 0) |
| 68 | i16 | `tv_moment_nm` | 0.0001 N·m | TV の PI が要求したヨーモーメント (左旋回が正。上限で丸めた後) |

- `flags` bit21 = `WHEEL_LIFT_ACTIVE`: 片輪浮き対策 (後輪左右の速度差・後輪周速の絶対上限) が
  トルクを削っている最中。このとき bit5 (`TC_ACTIVE`) は立たない。
- 実装: `Drive.torque_request_left/right_nm`、`Drive_GetTorqueRequestLeft/Right()`・
  `Drive_GetAbsLimit()`・`Drive_GetTvYawMoment()` (`src/control/drive.c`)、`src/comm/telemetry.c`。
- フレームは 91 バイト、100Hz で 9.1 kB/s (1Mbps の約9%)。

## 5. 上位 (Pi) 側の対応

- `protocol_version` の期待値を `0x0010` に。`TELEMETRY` の LEN を 84 に (`protocol.toml`)。
- `config/vehicle.toml` の `[control]` を唯一の定義とし、接続のたびに全項目を `CONFIG_SET` で
  送って `CONFIG_ACK.applied` と突き合わせ、その後も `CONFIG_GET` で読み戻し続ける
  (`raspi/core/control_params.py`)。
- 同定の試験は `DriveCmd.fw_overrides` で一時的に上書きする (試験の指令が届いている間だけ)。
