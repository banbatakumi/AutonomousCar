# SURGE Mark.2 UART プロトコル — v0.4 → v0.5 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-09
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要**

v0.4 (`pi_uart_protocol_v0.4_request.md`) からの差分のみを記す。
**変わったのは `COMMAND` (0x10) だけ**で、`TELEMETRY` / `LIDAR_SECTOR` / `PING` / `CONFIG_*` /
`VERSION` / `STATS` のレイアウトは v0.4 のまま一切変わっていない。

---

## 0. 要約

GUI から以下を操作できるようにするための変更である。

| 追加した操作 | 手段 |
|---|---|
| 灯火類の3段切替 (前後とも消灯 / DAYTIME / NORMAL) | `flags` bit3-4 を 2ビットの enum に拡張 |
| パッシング | `flags` bit5 を新設 |
| クラクション | 既存の `flags` bit2。**挙動を「押している間だけ鳴る」に変更** |
| ブレーキの強さ [N·m] | ペイロード末尾に `brake_torque : u16` を追加 (**LEN 10 → 12**) |

**`protocol_version` は `0x0004` → `0x0005` に上がる。**
`COMMAND` の LEN が変わるため、**Pi 側を更新するまで走行指令は一切通らない**
(STM32 は LEN 不一致のフレームを破棄し `STATS.rx_len_error` に計上する)。
中途半端に効いてしまうより完全に弾かれる方が安全なので、これは意図した破壊的変更である。

## 1. `COMMAND` (0x10) — LEN = 10 → **12**

```
off  size  type    field                 単位 / 備考
──────────────────────────────────────────────────────────────────────────────
  0    1   u8      mode                  0=DISARM / 1=MANUAL / 2=AUTO / 3=予約   (変更なし)
  1    1   u8      flags                 §1.1 ★ビット定義を変更
  2    2   i16     target_speed          0.001 m/s                               (変更なし)
  4    2   i16     target_steer          0.0001 rad 路面舵角、反時計回り正        (変更なし)
  6    2   u16     accel_limit           0.001 m/s²  0 = 未指定 (設定値を使う)   (変更なし)
  8    2   u16     steer_rate_limit      0.001 rad/s 0 = 未指定                  (変更なし)
 10    2   u16     brake_torque          0.0001 N·m  0 = 未指定 (最大で制動) ★新規
──────────────────────────────────────────────────────────────────────────────
                                                            合計 12 バイト
```

**フレーム長 = 12 + 7 = 19 バイト。100Hz で 1.90 kB/s。**

### 1.1 `flags` (u8) ビット定義 ★変更

| bit | 名称 | 意味 | v0.4 からの変化 |
|---|---|---|---|
| 0 | `arm` | 駆動電源投入を要求 | 変更なし |
| 1 | `brake` | ブレーキを掛ける | 変更なし (強さは `brake_torque` で指定) |
| 2 | `horn` | クラクション | **押している間だけ鳴るように変更** |
| 3-4 | `light_mode` | 前照灯モード (下表) | **★1ビットの `light` から 2ビットへ拡張** |
| 5 | `passing` | パッシング | **★新規** |
| 6-7 | — | 予約 (0 を入れること) | — |

#### `light_mode` (bit3-4)

| 値 | 名称 | 前照灯 | 尾灯 |
|---|---|---|---|
| 0 | `OFF` | 消灯 | 消灯 |
| 1 | `DAYTIME` | 減光 (duty 0.1) | 薄点灯 (duty 0.1) |
| 2 | `NORMAL` | 全光量 | 薄点灯 (duty 0.1) |
| 3 | 予約 | — | — (受信したら `NORMAL` として扱う) |

- **v0.4 の bit3 は「1=NORMAL / 0=DAYTIME」で、消灯が表現できなかった。**
  値の意味が変わっているので、`light = 1` をそのまま送ると `DAYTIME` になる点に注意。
- ブレーキランプは `light_mode` と独立で、`brake` が立っている間は尾灯が全光量になる。

#### `passing` (bit5)

- 立てている間、`light_mode` に関わらず**前照灯だけ**が全光量になる。
- **尾灯は連動しない。** 消灯状態でパッシングしたときに尾灯まで一緒に瞬くと、
  後続車から見て制動と紛らわしいため。
- 離せば `light_mode` の状態へ戻る (モードは保持されている)。GUI 側で
  「押している間だけ立てる」か「一定時間立てて自動で落とす」かは Pi 側の自由。

#### `horn` (bit2)

- **v0.4 では立ち上がりで 300ms の単発ビープだった。v0.5 では立てている間ずっと鳴る**
  (2500Hz の連続トーン)。GUI のボタンを押している間だけ `1` を入れること。
- 緊急停止発動時と `COMMAND` 途絶時は STM32 側で強制的に止める。

### 1.2 `brake_torque` (u16, 0.0001 N·m/LSB) ★新規

後輪 **各輪** に掛ける制動トルク。`flags.brake` が立っているときだけ意味を持つ。

- **`0` は「制動トルク 0」ではなく「未指定」を意味し、STM32 側の最大値で制動する。**
  `accel_limit` / `steer_rate_limit` と同じ約束。フィールドの埋め忘れでブレーキが
  効かなくなる方が危険なので、ゼロ値を安全側に倒してある。
- STM32 側の上限は **0.075 N·m/輪** (`DRIVE_MAX_BRAKE_TORQUE_NM`) で、超える値は
  クランプされる。**GUI のスライダは 0.0001〜0.075 N·m のレンジで作ること。**
  0.0001 N·m/LSB なので 750 段階あり、分解能は十分である。
- **`brake` が立っている間、車速 PI ループは完全に迂回される。** v0.4 では
  「目標車速を 0 にする」だけで、実際の制動力は PI ゲイン任せだった。
  v0.5 では MD を制動モード (`BRAKE_NM`) に切り替えて指定トルクを直接掛けるため、
  `brake_torque` がそのまま効く。`target_speed` はブレーキ中は無視される。
- ブレーキを離すと目標車速 0 から加速し直す (レート制限は `accel_limit` に従う)。
  ブレーキ中に `target_speed` を保持し続けても、離した瞬間に飛び出すことはない。

### 1.3 `TELEMETRY.torque_cmd[2]` の符号について (レイアウトは変更なし)

`torque_cmd` の意味を明確化する。**正 = 駆動、負 = 制動**である。

- ブレーキ中および停車保持中は、掛けている制動トルクが**負値**で入る
  (例: `brake_torque = 0.05 N·m` で制動中なら `-0.05`)。
- v0.4 では停車保持中に `0` を入れていたため、押さえているのか何もしていないのか
  区別が付かなかった。この変更で GUI からブレーキが効いていることを確認できる。
- 「車両が自分で駆動している」判定 (v0.4 §4.5) は**正の** `torque_cmd` を見ること。
  負値は制動なので走行開始の判定には使わない。

## 2. STM32 側の挙動変更 (プロトコルには現れないが Pi 側が知っておくべきこと)

### 2.1 起動時に駆動電源が一瞬 ON になる問題を修正

v0.4 の実装では、`Setup()` の中でステアリング原点の読み込みのために毎回 `DRIVE_POWER` を
一瞬 ON → OFF していた。**ボタン1を押しながら起動して原点較正をする場合を除き、
起動から Pi が `arm` するまで駆動電源は一度も投入されなくなった。**

`TELEMETRY.flags` bit2 (`armed`) の観測に影響がある。起動直後に一瞬だけ `armed` が
立つことは無くなったので、そちらを正とすること。

### 2.2 緊急停止・`COMMAND` 途絶時の制動が最大トルクになった

v0.4 では「目標車速 0」を与えるだけで、実際の減速は車速 PI 任せだった。
v0.5 では最大制動トルク (0.075 N·m/輪) を直接掛ける。**停止距離が短くなる。**
併せて、クラクションとパッシングは強制的に解除される
(舵角は最後の指令値のまま保持する。直進へ戻すと車体が予期しない方向へ動くため)。
