# SURGE Mark.2 UART プロトコル — v0.6 → v0.7 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-11
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要**

v0.6 (`pi_uart_protocol_v0.6_delta.md`) からの差分のみを記す。
**変わったのは `COMMAND` (0x10) の `flags` と `TELEMETRY` (0x02) の `flags` だけ**で、
両パケットとも **LEN は変わらない** (`flags` はすでに `COMMAND` は u8、`TELEMETRY` は u32 で
確保されており、空いていたビットを使うだけのため)。他のパケットも一切変わっていない。

---

## 0. 要約

前後超音波センサ (`us_distance_m`) を使い、**STM32 単独で障害物への自動停止**ができるように
した。有効/無効は Pi が `COMMAND.flags` で毎周期切り替えられる。

| 追加した操作 | 手段 |
|---|---|
| 自動停止の有効/無効切替 | `COMMAND.flags` bit7 に `auto_stop` を新設 |
| 自動停止が実際に作動中か | `TELEMETRY.flags` bit16 に `auto_stop_active` を新設 |

**`protocol_version` は `0x0006` → `0x0007` に上がる。**
`flags` のビット追加のみで LEN は変わらないため、**Pi 側が未対応でも通信自体は継続する**
(bit7 を立てなければ従来通りの挙動のまま)。ただし新しいビットを使いたい場合は
`protocol_version` を見て対応可否を判断すること。

## 1. `COMMAND` (0x10) — LEN 14 のまま変更なし

### 1.1 `flags` (u8) ビット定義 ★変更

| bit | 名称 | 意味 | v0.6 からの変化 |
|---|---|---|---|
| 0 | `arm` | 駆動電源投入を要求 | 変更なし |
| 1 | `brake` | ブレーキを掛ける (`auto_stop` より優先) | 変更なし |
| 2 | `horn` | クラクション (押している間だけ鳴る) | 変更なし |
| 3-4 | `light_mode` | 前照灯モード | 変更なし |
| 5 | `passing` | パッシング | 変更なし |
| 6 | `torque_mode` | 立っている間 `target_speed` を無視し、`target_torque` を後輪へ直接指令する | 変更なし |
| 7 | `auto_stop` | 立っている間、前後超音波の自動停止を有効にする | **★新規** (v0.6 までは予約) |

### 1.2 `auto_stop` (bit7) の挙動 ★新規

- 立っている間、進行方向の超音波距離 (`us_distance_m` と同じ前後センサ) が **20cm 未満**
  になると、STM32 が **自動で最大制動トルクをかけて停止**する。Pi からの `target_speed` /
  `target_torque` の指令値に関わらず割り込む。
- **進行方向の判定**: `torque_mode` が立っていなければ `target_speed` の符号、
  立っていれば `target_torque` の符号で前後どちらのセンサを見るか決める。
  `target_speed >= 0` (前進・停止) なら前方センサ、負 (後退) なら後方センサだけを見る。
  **逆方向のセンサは見ない** (前方に障害物があっても `target_speed` を負にすれば後退できる)。
- 検知不能 (`ULTRASONIC_NO_ECHO`、対象が検知範囲にいない) のときは作動しない。
- **`brake` (bit1) が同時に立っている場合は `brake` が優先**し、その制動トルクは
  `brake_torque` (未指定なら最大) をそのまま使う。`auto_stop` 単独での作動時は
  常に最大制動トルクを使う (`brake_torque` の値は見ない)。
- `torque_mode` と同時に立っていても、`torque_mode` 中の TC/TV と同じ経路には乗らず
  ブレーキが優先される (v0.6 の `brake` と `torque_mode` の優先順位と同じ扱い)。
- 停止後、障害物が離れて検知距離を上回ればその周期から自動的に解除される
  (ラッチしない。ヒステリシスも無いため、しきい値付近ではチャタリングし得る点に注意)。
- ヒットするセンサは前後の超音波 (`RangeSensor`) のみ。**LiDAR は今回使っていない**
  (360点の最小距離配列を使った全周の自動停止は別途 `src/sensing/lidar.c` 側の拡張が必要で、
  現状は未実装のまま)。

## 2. `TELEMETRY` (0x02) — LEN 変更なし

### 2.1 `flags` (u32) ビット定義 ★追加

| bit | 名称 | 意味 | v0.6 からの変化 |
|---|---|---|---|
| 16 | `auto_stop_active` | 自動停止が直近の周期で実際に制動へ介入した (`auto_stop` が有効かつ検知中) | **★新規** |

`auto_stop_active` は「`auto_stop` ビットが立っている」ではなく「実際に超音波が
しきい値未満を検知して制動している」ことを示す。有効/無効そのものは Pi 側が
自分で送った `COMMAND.flags` の値を覚えていれば分かるため、テレメトリには載せていない。

## 3. Pi 側の対応チェックリスト

- [ ] `COMMAND.flags` bit7 `auto_stop` を送れるようにする (GUI/AUTO のトグル等)
- [ ] `TELEMETRY.flags` bit16 `auto_stop_active` を受信・表示できるようにする
      (自動停止が作動して急に減速したことを Pi 側のログ/GUI で説明できるようにするため)
- [ ] `protocol_version` の期待値を `0x0006` → `0x0007` にする
- [ ] `auto_stop` を有効にしたまま `brake` や `torque_mode` を使う場合の優先順位
      (`brake` > `auto_stop` > 通常指令) を把握しておく (STM32 側で二重制御する必要は無い)
- [ ] 検知距離 (20cm) 前後でのチャタリングを許容できない用途では、Pi 側で
      `us_distance_m` を見て `auto_stop` を早めに使う/使わないよう調停することを検討する
      (STM32 側にヒステリシスは無い)
