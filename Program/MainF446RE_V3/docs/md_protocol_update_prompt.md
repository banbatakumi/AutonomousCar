# MD ファームウェア改修プロンプト

上位 STM32 (MainF446RE_V3) 側のプロトコル実装を刷新したため、MD 側を対応させる必要がある。
以下をそのまま MD ファームウェアのリポジトリで Claude Code に渡すこと。

---

BLDC モータドライバ (MD) のシリアル通信プロトコルを改修してください。上位の車両制御基板
(STM32F446RE) 側は実装済みで、以下の仕様で確定しています。MD 側をこれに合わせてください。

## 改修の目的

1. **トルク上限を上位から設定できるようにする** (最重要)。現在 MD 内部に固定値で
   持っている制限を、上位が指定した値で動的に設定する。据え切りやラックエンドで位置偏差が
   残り続けたときに速度ループがワインドアップして電流を流しっぱなしになるのを防ぐのが主目的。
   絶対に超えてはいけない最大の上限は変わらずMD側の定数で設定しておくこと．
2. **フレームに CRC-8 を導入する**。現在のフレームはヘッダ `0xAA` とフッタ `0xFF` だけで、
   フッタは固定値なのでペイロードの化けを一切検出できない。データ部にも `0xAA` / `0xFF` は
   現れうるため、バイト落ちで同期がずれるとデタラメなフレームを受理する。
3. **状態フレームに、MD が実際に適用している制限値をエコーバックさせる**。上位が
   「制限が本当に効いているか」を確認できるようにする。

制限値は設定コマンドとして別送するのではなく、**毎回の指令フレームに載せます** (CANopen の
RxPDO 相当)。フレーム 1 つが常に完結した状態を表すため、取りこぼしても MD がリセットしても
次のフレームで復元され、設定値の同期という問題自体が発生しません。

## 共通仕様

- UART **250000 bps, 8N1** (変更しない)
- 多バイト値はすべて**ビッグエンディアン**
- 両方向ともフッタは**廃止**。末尾は CRC-8 のみ
- CRC は **CRC-8/AUTOSAR**: `poly=0x2F, init=0xFF, xorout=0xFF, 入出力ビット反転なし`
  - AUTOSAR CRC ライブラリの `Crc_CalculateCRC8H2F` と同一
  - **チェック値**: `"123456789"` (`0x31`〜`0x39` の 9 バイト) に対して **`0xDF`**
- CRC の計算対象は「先頭の `0xAA` を除き、CRC 自身の手前まで」
- **CRC 不一致のフレームは破棄し、前回値を保持する**。誤った値で制御するより 1 周期古い
  正しい値を使う方が安全。破棄した数はカウンタに持つこと (通信品質の確認用)

参照実装:

```c
#define CRC8_POLY 0x2F
#define CRC8_INIT 0xFF
#define CRC8_XOROUT 0xFF

static uint8_t Crc8(const uint8_t* data, uint8_t len) {
  uint8_t crc = CRC8_INIT;
  for (uint8_t i = 0; i < len; i++) {
    crc ^= data[i];
    for (uint8_t bit = 0; bit < 8; bit++) {
      crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ CRC8_POLY) : (uint8_t)(crc << 1);
    }
  }
  return crc ^ CRC8_XOROUT;
}
```

## 受信フレーム (上位 → MD): 6 バイト固定長

| オフセット | 内容 | 型 | 備考 |
|---|---|---|---|
| 0 | `0xAA` | u8 | ヘッダ |
| 1 | mode | u8 | 下表の header |
| 2–3 | setpoint | **i16** BE | スケールは mode ごと |
| 4 | torque_limit | **u8** | × 0.001 → 0〜0.255 N・m |
| 5 | crc8 | u8 | byte1–4 に対する CRC-8 |

torque_limit のスケールはモータ最大 0.1557 N・m に合わせて詰めてある (分解能 1 mN・m、
モータ最大まで 155 段階)。電流センサの量子化 0.0081 A/LSB = 0.158 mN・m と釣り合う粒度。

**速度上限は持ちません。** 位置制御では速度指令が `Kp × 位置偏差` で決まり、ステアリングの
偏差は機構的に有界 (±60 度) なので位置ゲイン自体が速度リミッタとして働きます。後輪は
トルクモードで駆動しており、過速度の歯止めは上位の車速リミッタ側で持ちます。

mode とスケール (**現行の `SERIAL_COMMANDS` テーブルから変更しない**):

| header | モード | スケール | 単位 | i16 レンジ |
|---|---|---|---|---|
| `0xBA` | 角速度指令 | 0.01 | rad/s | ±327.67 |
| `0xBB` | 位置指令 | 0.001 | rad | ±32.767 |
| `0xBC` | トルク指令 (Iq) | 0.001 | A | ±32.767 |
| `0xBD` | トルク指令 | 0.0001 | N・m | ±3.2767 |
| `0xBE` | 制動電流指令 | 0.001 | A | ±32.767 |
| `0xBF` | 制動トルク指令 | 0.0001 | N・m | ±3.2767 |

上位は **1 kHz** でこのフレームを送ります (250000 bps で 6 バイト = 240 µs)。

## 送信フレーム (MD → 上位): 11 バイト固定長

| オフセット | 内容 | 型 | スケール |
|---|---|---|---|
| 0 | `0xAA` | u8 | ヘッダ |
| 1 | status | u8 | bit3:過電流 bit2:過熱 bit1:電源電圧異常 bit0:動作中 |
| 2 | temperature | u8 | 1 degC |
| 3–4 | theta | **u16** BE | 0.0001 rad (0.1 mrad) |
| 5–6 | speed | **i16** BE | 0.01 rad/s |
| 7–8 | iq | **i16** BE | 0.001 A (1 mA) |
| 9 | torque_limit | **u8** | × 0.001 N・m — **適用中**の値 |
| 10 | crc8 | u8 | byte1–9 に対する CRC-8 |

byte 1〜8 は現行の状態フレームと同じ内容・同じスケールです。byte 9 の追加と、
フッタ `0xFF` を CRC に置き換えるのが変更点です。

## 制限値の適用要件

1. **`torque_limit` はトルク (電流) 指令の飽和値**。速度ループ・位置ループの出力をこの値で
   クランプし、**飽和中は積分項のアンチワインドアップを効かせること**。これが無いと、
   据え切りでラックエンドに当たった状態が続いたときに積分が溜まり続け、電流を流しっぱなしに
   してモータと FET を焼きます。今回の改修で最も重要な項目です。
2. **制動モード (`0xBE` / `0xBF`) の制動トルクも `torque_limit` で頭打ちにすること。**
3. **エコーバックする値は、受信値そのままではなく MD 内部で実際に適用している値**にすること。
   MD 固有のハードウェア上限があるなら、受信値とその上限の小さい方を返す。上位から
   「本当に効いている制限」が見えることに意味があります。
4. **起動直後の既定値は 0 (= 上限 0、動かない)** とする。制限値を受け取れていない状態で
   モータが回らないのが正しい挙動です。**「0 = 無制限」という解釈にしないでください。**
   フェイルオープンになり、通信失敗が全力回転につながります。

## 変更しないもの

- ボーレート (250000 bps 8N1)、および mode header の値 (`0xBA`–`0xBF`)
- 指令値・状態値のスケール (上表のとおり現行維持)
- **無通信 0.5 秒での停止モード遷移** (上位はこれを停止手段として使っています)
- status ビットの割り当て

## テストベクタ

実装後、以下で往復を確認してください。いずれも上位側の実装で検証済みの実データです。

**受信 (上位 → MD)** — 位置指令 0.5 rad / トルク上限 0.050 N・m:

```
AA BB 01 F4 32 26
```

`0x01F4` = 500 → 500 × 0.001 = 0.5 rad、`0x32` = 50 → 0.050 N・m、
CRC は byte1–4 (`BB 01 F4 32`) に対して `0x26`。

**送信 (MD → 上位)** — status=過電流+動作中 / 42 degC / theta 1.0 rad / speed −12.34 rad/s /
iq 2.5 A / トルク上限 0.050 N・m:

```
AA 09 2A 27 10 FB 2E 09 C4 32 7C
```

CRC は byte1–9 に対して `0x7C`。

## 受け入れ条件

- [ ] `Crc8("123456789", 9)` が `0xDF` を返す
- [ ] 上記 2 つのテストベクタが、生成側・解析側の両方で一致する
- [ ] 受信フレームの任意の 1 ビットを反転させると必ず破棄される (byte1–4 の 32 通りすべて)
- [ ] データ部に `0xAA` を含むフレームを正常にパースできる
- [ ] 途中で 1 バイト欠落させても、後続フレームで同期が復帰する
- [ ] 無通信 0.5 秒で従来どおり停止モードに入る
- [ ] 位置制御中にモータ軸を機械的に固定したとき、電流が `torque_limit` 相当で頭打ちになり、
      拘束を解いても飛び出さない (アンチワインドアップの確認)
