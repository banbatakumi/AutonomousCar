# SURGE Mark.2 UART プロトコル — v0.11 → v0.12 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-25
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要 (実機での動作検証は未了)**

v0.11 (`pi_uart_protocol_v0.11_delta.md`) からの差分のみを記す。
**`COMMAND`/`TELEMETRY` を含めどのパケットも構造・LEN は変わっていない。**
変わったのは `CONFIG_SET`/`CONFIG_GET` で使える `param_id` が増えたことと、
`RAS_CMD_FLAG_AUTO_STOP` (COMMAND.flags bit7) の下位側の判定ロジックそのもの。

---

## 0. 要約

自動停止 (`RAS_CMD_FLAG_AUTO_STOP`) の判定を、固定20cmの超音波単独判定から、
「車速から物理的に導かれる動的停止距離」+「LiDARを主センサとしたセーフティゾーン判定」+
「超音波を補助センサとした2つの役割」の組み合わせへ全面刷新した。

**動的停止距離の式** (前後方向、実車速の絶対値 `v` を使う):

```
d_stop = v・t_delay + v²/(2・a_max) + margin
```

- `t_delay`, `a_max` は下位 (STM32) 側の固定定数 (`VEHICLE_AUTO_STOP_DELAY_S`,
  `DRIVE_MAX_ACCEL_M_S2` を制動側の近似として流用)。**いずれも未実測プレースホルダー**。
- `margin` (安全マージン) は段階的なレベルではなく、Pi から `CONFIG_SET`/`CONFIG_GET` で
  **cm単位の値を直接指定**する連続値。

| 追加した操作 | 手段 |
|---|---|
| 自動停止マージン [cm] の設定 | `CONFIG_SET` の `param_id = 0x0060` |
| 現在のマージンの取得 | `CONFIG_GET` の同じ `param_id` |

**`protocol_version` は `0x000B` → `0x000C` に上がる。**
`CONFIG_SET`/`CONFIG_GET` は元々未知の `param_id` に対して `RAS_CONFIG_UNKNOWN_PARAM`
を返す設計だったため、**Pi 側が未対応でも通信自体は継続する** (この `param_id` を
送らなければ既定 15cm のまま変わらない)。

**互換性の注意**: 旧v0.7〜v0.11の固定20cmしきい値とは挙動が異なる。停車中 (v=0) は
マージンのみが効くため、既定では15cmで作動する。走行中は車速が上がるほど `d_stop` が
伸び、より早い段階で作動するようになる。固定値との互換を前提にしないこと。

## 1. `CONFIG_SET` (0x11) / `CONFIG_GET` (0x13) — LEN 変更なし

### 1.1 `param_id` 一覧 ★追加

| param_id | 名称 | 型 | 値の意味 |
|---|---|---|---|
| 0x0060 | `auto_stop_margin_cm` | f32 | 安全マージン [cm]。範囲 0.0〜100.0、既定15.0 |

- ペイロード形式は既存の `CONFIG_SET`/`CONFIG_GET`/`CONFIG_ACK` と同じ (`param_id` u16 +
  `value`/`applied` f32)。段階的なレベルではなく、cm単位の値をそのまま送る。
- `CONFIG_ACK.applied` には実際に適用された値が入る。範囲外 (0.0〜100.0 の外) を送った
  場合はクランプして適用し、丸めが発生したぶん `result` は `RAS_CONFIG_OUT_OF_RANGE` になる。
- このパラメータが切り替えるのは **安全マージン `margin` のみ**。動的停止距離の物理項
  (`v・t_delay + v²/2a_max`) は常に一定。

### 1.2 自動停止の判定ロジック (`RAS_CMD_FLAG_AUTO_STOP`)

進行方向 (実車速の符号。前進中に後退を指令した瞬間も実車速で判定するため、
瞬間的に反対側のセンサへ切り替わって障害物を見失う窓ができない) について:

1. **LiDAR (主センサ)**: 前方0度・後方180度を中心に±20度のセーフティゾーン (角度窓) を見る。
   窓内の1度ビンのうち、直近300ms以内に更新されていて `d_stop` 以内の距離を示す点の数を数え、
   **3点以上**あれば障害物ありと確定する。単発ノイズは1点しか占めないため、時間方向の
   デバウンスではなく空間方向の点密度で誤検知を弾く設計。
2. **超音波 (補助・フォールバック)**: LiDARのセーフティゾーン窓内に直近300ms以内の
   データが1点も無い (死角・センサ不調) 場合のみ、超音波の距離を `d_stop` と比較して
   フォールバック判定する。
3. **超音波 (補助・至近距離の独立トリガー)**: LiDARの結果に関わらず、超音波が **5cm未満**
   を検知したら常に作動する。LiDARの最短測距距離や取付高さの死角 (バンパー直前など) を
   補う保険。

上記いずれかが真なら、進行方向の超音波を問わず自動停止が作動する (OR判定)。
解除は引き続き即時・ヒステリシス無し (しきい値を上回れば次周期で即座に解除)。
ラッチはせず、上位からの解除操作も不要。

## 2. Pi 側の対応チェックリスト

- [ ] `protocol_version` の期待値を `0x000B` → `0x000C` にする
- [ ] 自動停止のマージンを変更したい場合のみ `CONFIG_SET` (`param_id = 0x0060`, cm単位の
      f32値) を送る (送らなければ既定15cmのまま変わらない)
- [ ] 現在の設定値を確認したい場合は `CONFIG_GET` で同じ `param_id` を問い合わせる
- [ ] 旧バージョンの「固定20cm」を前提にしたロジックが Pi 側にあれば、動的停止距離
      (走行速度が上がるほど早期に作動する) に合わせて見直す
- [ ] **実機での動作検証は STM32 側でも未実施。** `t_delay`・`a_max` (制動側への流用)・
      LiDAR点数しきい値・超音波5cmトリガーはいずれも実測前の値であり、誤介入・
      未介入が疑われる場合は一度 `RAS_CMD_FLAG_AUTO_STOP` を下げて切り分けることを推奨する
