# SURGE Mark.2 UART プロトコル — v0.13 → v0.14 差分

**発信**: STM32F446RE 車両制御基板 (MainF446RE_V3) 開発側
**宛先**: Raspberry Pi 5 側 開発担当
**日付**: 2026-08-30
**状態**: STM32 側 実装済み・ビルド確認済み。**Pi 側の対応が必要 (実機での動作検証は未了)**

v0.13 (`pi_uart_protocol_v0.13_delta.md`) からの差分のみを記す。変わったのは `COMMAND`
(0x10) の `flags2` と `TELEMETRY` (0x02) の `flags` の空きビットのみ。**ワイヤ形式・LEN の
変更は無い** (既存フィールドのビット割り当てが増えるだけ)。

---

## 0. 要約

自律走行 (AUTO) 中に右左折・車線変更の意思表示ができるよう、上位からウィンカーを点滅させら
れるようにした。ウィンカー自体の点滅パターン制御は `src/lighting/` に既にあったが、上位指令
から一度も呼ばれていない実装漏れだった。

**`protocol_version` は `0x000D` → `0x000E` に上がる。`COMMAND`・`TELEMETRY` とも LEN は
変わらない。**

---

## 1. `COMMAND` (0x10) — `flags2` (bit1-2) 追加

| bit | 内容 |
|---|---|
| 0 | `SIDE_BRAKE` (既存, v0.13) |
| 1 | `WINKER_LEFT` (新設) |
| 2 | `WINKER_RIGHT` (新設) |

- 立っている間、左/右ウィンカーを点滅させる。`brake`/`horn`/`passing` と同じく「上位が
  送り続けている間だけ有効」な継続コマンドで、ラッチはしない。
- **bit1・bit2 が両方立っていればハザード (左右同時点滅) として扱う。** 専用のハザード
  ビットは設けていない。
- 点滅の周期・位相は `src/lighting/lighting.c` の既存パターン (フェードイン→保持→
  フェードアウト→間隔) をそのまま使う。上位側で個別に周期を作る必要はない。
- **フォールト表示 (電源異常・緊急停止によるハザード点滅、`src/hmi/indicator.c`) の方が
  優先する。** フォールト中はこのビットの状態に関わらず両輪とも点滅 (ハザード) になる。
- `COMMAND` 途絶・緊急停止では `horn`/`passing` と同様に強制的に消灯する。

## 2. `TELEMETRY` (0x02) — `flags` (bit18-19) 追加

| bit | 内容 |
|---|---|
| 17 | `SIDE_BRAKE_ACTIVE` (既存, v0.13) |
| 18 | `WINKER_LEFT_ACTIVE` (新設) |
| 19 | `WINKER_RIGHT_ACTIVE` (新設) |

- 左/右ウィンカーが実際に点滅中かどうか。上記の優先度調停の結果を反映するため、
  **上位が要求したビットと必ずしも一致しない** (フォールト中は要求に関わらず両方立つ)。
- `flags` は元々 `uint32_t` で確保済みのため、`TELEMETRY` の LEN・既存フィールドへの
  影響はない。

## 3. Pi 側の対応チェックリスト

- [ ] `protocol_version` の期待値を `0x000D` → `0x000E` にする
- [ ] `COMMAND` の `flags2` bit1/bit2 に、それぞれ左/右ウィンカー要求を立てて送る
      (両方立てるとハザード)。ワイヤ形式・送信長は変わらないため、対応しない場合も
      既存の送信コードのままで動作に支障はない
- [ ] `TELEMETRY.flags` の bit18/19 (`WINKER_LEFT/RIGHT_ACTIVE`) をデコードし、実際の
      点灯状態を UI 等で表示する場合に使う。フォールト中は要求と異なりうることに注意
- [ ] **実機での動作検証は STM32 側でも未実施。** 点滅周期・フォールトとの優先度調停が
      意図通りかを実車で確認しながら進める想定
