# SURGE Mark.2 UART プロトコル — v0.17 → v0.18 差分

**日付**: 2026-10-08
**状態**: STM32 側・Pi 側とも実装済み・ビルド確認済み。**STM32 は未書き込み、実機での動作検証は未了**

v0.17 (`pi_uart_protocol_v0.17_delta.md`) からの差分のみを記す。**ワイヤ形式 (LEN・オフセット) は同じ**で、
変わるのは**舵角の数値の意味**と `CONFIG_SET`/`CONFIG_GET` の `param_id` の追加。

---

## 0. 要約

1. **舵角は実際の路面舵角になった** (§1)。v0.17 までは「ステアモータの角度 × 0.5」で、リンクが線形で
   ないため大舵角で実際より大きかった。
2. **`param_id` `0x0081`・`0x0082` (リンクの換算) を新設** (§2)。入れた瞬間に反映し、`LIMITS` を送り直す。
3. **車速 (`TELEMETRY.speed`) が舵いっぱいで 2〜6% 大きく (正しく) なる** (§3)。

**`protocol_version` は `0x0011` → `0x0012` に上がる。上位と必ず一緒に入れ替えること** (片方だけだと
舵角の意味が食い違う。§4)。

---

## 1. ステアのリンクの換算 (`src/control/steering.c`)

```
x        = モータ角 × STEERING_LINKAGE_RATIO (0.5)      可動範囲 ±30° (モータ角 ±60°)
路面舵角 = steer_link_gain × x + steer_link_cubic × x³
```

- 指令 (`Steering_SetRoadWheelAngleRad`): 路面舵角を可動範囲へ丸めてから、ニュートン法 (4回) で x に戻す。
- 報告 (`Steering_GetRoadWheelAngleRad`)・可動範囲 (`Steering_GetMaxRoadWheelAngleRad`) は式をそのまま通す。
- 可動範囲の端での傾き `gain + 3·cubic·x²` が `STEERING_LINKAGE_MIN_SLOPE` (0.3) を下回る `cubic` は、
  下回らない値へ丸める (傾きが 0 以下だと逆変換が一意に決まらない)。`CONFIG_ACK.applied` は丸める前の
  値を返すので、上位は範囲に余裕のある値だけを送ること (今の同定値の端の傾きは 0.67)。
- 既定は `gain` = 1・`cubic` = 0 (= v0.17 までと同じ)。上位が接続のたびに同定値を送る。

### 根拠 (2026-10-08 の定常円旋回。横加速度が小さくタイヤがほぼ滑っていない区間)

| 求め方 | 前輪の向き |
|---|---|
| 報告値 (モータ角 × 0.5) | 29.1° |
| 後輪と前輪の速度比 (cos⁻¹) | 26.7° |
| 曲率 (ヨーレート ÷ ファームの車速) | 26.3° |
| 曲率 (ヨーレート ÷ 後輪の車速) | 25.8° |

リンクが複雑で設計から式を出せないため、上位のシステム同定 (舵角ごとの曲率) で `gain`・`cubic` を決める。
上位は以前からこの非線形を `steer_gain`・`steer_gain_cubic` で補っていたが、このファーム自身が路面舵角を
使う (§3) ので、換算をファームへ移した。

## 2. `CONFIG_SET` / `CONFIG_GET`

名前・`param_id`・既定値・範囲の唯一の定義は `src/control/control_params.h` の表。

| `param_id` | 名前 | 既定値 | 範囲 | 内容 |
|---|---|---|---|---|
| `0x0081` | `steer_link_gain` | 1.0 | 0.5〜1.5 | 路面舵角 = これ × x + cubic × x³ |
| `0x0082` | `steer_link_cubic` | 0.0 | -1.5〜1.5 | 同 3次の項 [1/rad²] |

- `CONFIG_SET` を受けた瞬間に `Steering_SetLinkage()` へ渡す (`src/comm/ras_link.c` の `ApplyConfig`)。
- **路面舵角の可動範囲が変わるので `LIMITS` (0x09) を送り直す** (`max_steer_rad`)。上位は `LIMITS` を
  1回受けたら再要求しない実装なので、こちらから送らないと古い上限で指令を丸め続ける。
- 今の同定値 (gain 0.9928・cubic -0.3917) では `max_steer_rad` は 0.5236 (30°) → 0.4636 (26.56°)。
- Flash には保存しない (他の調整パラメータと同じ)。電源を入れ直すと 1 と 0 に戻る。

## 3. 舵角を使っている箇所への波及

換算は Steering の入出力で閉じているので、コードの変更は無い。値だけが変わる。

- **車速** (`EstimateVehicleSpeed`、`src/control/drive.c`): 前輪の速度 × cos(路面舵角)。v0.17 までは角度が
  大きすぎたので、舵いっぱいで 2.2% (低い横加速度) 〜 5.9% (限界付近) 小さく出ていた。換算後は
  低い横加速度でのずれが消える (横加速度とともに増える分は前輪の横滑り角で、これは残る)。
- **TC のスリップ率**: 基準が上の車速なので、旋回中に両後輪が常に空転して見えていた分が減る。
- **TV の横加速度** (車速 × ヨーレート)・**オドメトリ** (上位が `speed` を積む) も同じ。
- **舵角のレート制限・エコー** (`src/vehicle/vehicle.c`) は路面舵角の単位のまま。同じ 7rad/s でも、
  モータの角速度は大舵角で最大約 1.5 倍になる (傾き 0.67 の逆数)。

## 4. 上位との組み合わせ

| ファーム | 上位 | 起きること |
|---|---|---|
| v0.18 | v0.18 | 正しい。上位が `steer_link_*` を送り、`control_params_status` が `ok` |
| v0.17 以前 | v0.18 | **舵が切れ足りない**: 上位は路面舵角 (最大 26.56°) を送るが、ファームは「モータ角 × 0.5」と解釈する (26.56° の指令で前輪は約 24.1°)。`steer_link_*` に `UNKNOWN` を返すので上位の `control_params_status` は `unsupported` |
| v0.18 | v0.17 以前 | 換算なし (既定の 1 と 0) で動くので v0.17 と同じ挙動 |

---

## 5. 関連する変更

- `Steering_SetLinkage(float gain, float cubic)` を追加 (ステアは1つなのでモジュールで1組だけ持つ)。
- `host/` (ホスト向けコンパイル) は `steering.c` を含まないので影響なし (舵角は車両モデルから直接渡す)。
- 上位側: システム同定が「報告された舵角 → 曲率」の効きを、記録時の換算の上に重ねて `steer_link_*` を出す
  (`tools/sysid/analyze.py` の `fold_steer_link`)。`config/vehicle.toml` の `[control]` に書く。
